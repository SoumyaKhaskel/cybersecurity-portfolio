# Portfolio assets

## Project screenshots

Place screenshots and diagrams in `images/projects/<project-slug>/`. The site currently uses:

- `cybersecurity-news-agent/FINAL_Working.png` as the lead image, with `CNA2_Web.png` and `telegram alerts.png` as supporting views.
- `network-performance-optimization/before.png` and `after.png` as comparison images, plus `SG TCP Optimizer Settings Window.png` as a redacted settings view.

Use descriptive filenames for future additions, for example `01-overview.png`, `02-architecture.png`, and `03-results.png`. Keep each project to two to four images. In the portfolio, each image opens in the zoom viewer.

The replaced settings screenshot has a blanked local IP address field. Check screenshots again before publishing if you replace or add any project evidence.

## Certificates

- `certificates/` contains the original PDFs supplied for the portfolio.
- `images/certificates/` contains first-page PNG previews rendered from those PDFs. The page opens previews in the zoom viewer and links to the original PDF.
- Add later certificates as PDFs with descriptive filenames. Confirm the exact credential name, issuing platform, completion date, and public verification destination before adding a portfolio entry.

## Other assets

- `resume/`: approved downloadable resume PDF.
- `images/brand/`: your logo when ready.
- `images/profile/`: optional portrait or avatar, only if you choose to include one.
- `images/placeholders/`: clearly labeled demo placeholders for project imagery that has not yet been supplied.

Before publishing new files, remove credentials, tokens, private infrastructure details, and confidential company information. A private LAN IP can still reveal information about your local network setup, so redact it from screenshots intended for the public site.
